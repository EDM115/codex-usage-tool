# Maintaining the pricing cache

Use this checklist whenever `src/openai-pricing-cache.ts` changes. A refreshed page alone does not update release dates, historical prices, aliases, or presentation metadata. Start with `git diff --cached -w -- src/openai-pricing-cache.ts` to separate meaningful changes from copied Markdown whitespace, then inspect the ordinary diff for parser-sensitive indentation. Preserve existing staged content and leave implementation edits unstaged for review.

## Sources and dates

Verify model IDs and rates against the [OpenAI pricing reference](https://developers.openai.com/api/docs/pricing), and release dates and billing announcements against the [API changelog](https://developers.openai.com/api/docs/changelog), model pages, or launch announcements. Keep three separate dates: the cache refresh date, model availability date, and each price period's effective date. A snapshot suffix, a cache refresh, and an announced billing start are not interchangeable.  
Record the supporting URL in the catalog or pricing period. Keep older periods when prices change. Do not infer an alias merely because two models cost the same, and do not infer that a newly listed specialized model becomes the default Codex model.

## September 2026 example and limits

The September 16 snapshot adds `gpt-image-2.5-sunburst`, `gpt-image-2.5-flare`, `gpt-rosalind-research`, and duration-priced `gpt-live-1`. The first three became available September 8; GPT-Live became available September 10. All remain non-primary, so Astra remains the inferred primary. These dates are recorded in the [official changelog](https://developers.openai.com/api/docs/changelog).  
Sunburst and Flare are separate model IDs, not aliases of GPT Image 2. Their supported estimate uses text input at $5/M, cached text input at $1.25/M, and image output at $30/M. `TokenBreakdown` does not distinguish text and image input, so this is the same approximation already used for GPT Image 2, not full image billing. Image input has a different published rate. The grouped-table parser also reads older GPT Image rows and their explicit Batch rates; missing Fast/Batch rows are not manufactured.  
Rosalind has a zero-cost period from September 8 through October 4, then $5/M input, $0.50/M cached input, and $25/M output from October 5. `ROSALIND_BILLING_START` protects this date during live loading as well as bundled loading. There is no cache-write charge. The raw current table contains the announced paid rates; dated cost estimation uses the catalog.  
GPT-Live sessions cost $0.05/minute, billed per second, with backend model/tool usage charged separately. The catalog records its availability, but it has no per-token rate. The token estimator cannot calculate the session charge: do not convert $0.05/minute into $0.05/M tokens or a zero-cost token row. Unknown/unpriced token events retain the tool's normal fallback estimation; that is not GPT-Live billing. Duration billing would require separate usage fields and estimation support.  
The removed `gpt-5.4-cyber` row contained only missing-price markers. Keep its historical model definition; removal of an unpriced row is not evidence to delete a model or redirect its aliases. Existing Daybreak and review-model aliases retain their dated mappings unless a new authoritative mapping is supplied.

The September 23 cache adds `gpt-6-sol` and `gpt-6-luna`, which the [API changelog](https://developers.openai.com/api/docs/changelog) dates to September 22. Both have published short- and long-context rates for Standard, Batch, Flex, and Fast mode. They are canonical IDs with no documented shared `gpt-6` alias. Astra remains the inferred primary because model availability alone does not identify a replacement default. `gpt-5-search-api` was already present in the September 16 cache; its first-observed date is pinned in the model catalog so advancing `BUNDLED_PRICING_DATE` does not erase that historical pricing period. A live fetch with an earlier effective date must skip models not yet released.

## Verification sequence

1. Review the staged semantic diff and collect source evidence before editing metadata.
2. Add a focused regression for any new parser behavior or pricing boundary, and confirm it fails before the fix. A bundled refresh must preserve existing historical-price tests.
3. Run the focused pricing suite, regenerate the fixture, then run all tests and type checking:

```pwsh
bun test tests/pricing.test.ts
bun run demo
bun test
bun run typecheck
bun usage help
git -c core.whitespace=-blank-at-eol diff --check
git diff --stat
git diff --cached --stat
```

The whitespace check above allows the repository's intentional two-space Markdown hard line breaks. A plain `git diff --check` reports those as trailing whitespace; inspect them without stripping required line breaks.  
4. If parser behavior changed, smoke-test `loadPricing` against the live OpenAI page and verify representative rates, tiers, and provenance. Keep this separate from deterministic unit tests. A live warning can indicate network failure or format drift even when fallback results look reasonable. 5. Inspect `git diff -- demo.json`: catalog-only work should normally change model metadata, not historical usage totals. For presentation changes, `bun run demo:report` writes an ignored HTML report to `output/demo/usage-report.html`. 6. Verify the originally staged blob is unchanged with `git ls-files -s src/openai-pricing-cache.ts`, compared with its value recorded before editing. Report test results and any live-only limits; leave staging and commits to the maintainer.
